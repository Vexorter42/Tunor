# Tunor

Графический интерфейс для [sing-box](https://github.com/SagerNet/sing-box) на **Windows, macOS и Linux** с поддержкой **AmneziaWG 1.0 / 2.0 / 3.x**: туннели, правила маршрутизации, помощники генерации конфигов и обновление «по воздуху».

> A Windows, macOS and Linux GUI for sing-box with AmneziaWG (1.0 / 2.0 / 3.x) — tunnels, routing rules, guided config generation and OTA updates.

До версии 1.10.0 проект назывался **Nyx**; имя сменилось из-за большого числа одноимённых проектов. Старые ссылки на репозиторий продолжают работать.

## Что умеет

**Туннели**

- **AmneziaWG 1.0 / 2.0 / 3.x** — движок на базе [sing-box-lx](https://github.com/Leadaxe/sing-box-lx). Поддерживаются `Jc/Jmin/Jmax`, `S1–S4`, `H1–H4`, `I1–I5`, а также 3.x: `ContentPaddingAddition`, `RekeyAfterTime`, `RejectAfterTime`, `KeepaliveTimeout`, `MaxHandshakeAttempts`, `RandomTrailers`, `DisableCookies`.
- **Свой VPN по ссылке** — VLESS, VMess, Trojan, Shadowsocks. Ссылка разбирается и показывается человеческим языком: сервер, тип шифрования, транспорт. Нечитаемая ссылка не попадает в конфиг, а объясняет, что в ней не так.
- **Подписки** — вместо отдельной ссылки адрес подписки: приложение скачивает список серверов. Сервер выбирается вручную или отдаётся движку, который замеряет задержку и уходит с того, что перестал отвечать.
- **Туннелей столько, сколько нужно.** WARP и geo — просто первые два в списке; любой можно пустить **внутрь** другого. Так и работает исходная идея: geo идёт цепочкой через WARP, а свой VPN остаётся доступным там, где его адрес заблокирован.
- **Сломанный конфиг не роняет остальные.** Ключи и ссылки проверяются до сборки конфига: негодный туннель в конфиг не попадает, а приложение говорит, что именно с ним не так — кавычки, невидимый символ, обрезанный ключ.
- **Свой генератор конфига** — `config.json` собирается приложением из туннелей, правил и настроек. Внешние утилиты не нужны.

**Маршрутизация**

- **Правила** — группы `inline` (домены и программы), `remote` (внешние `.srs`) и `local` (локальные списки). Домен в списке покрывает и поддомены: `youtube.com` включает `www.youtube.com`, но не `notyoutube.com`. Группы создаются, переименовываются и удаляются прямо в приложении; начало имени решает, в какой туннель пойдёт группа, и приложение пишет об этом под полем.
- **«Куда пойдёт»** — вписываешь домен, ссылку, IP или имя программы и сразу видишь, каким путём он пойдёт и какое правило сработало.
- **Раздел «Приложения»** — показывает, к каким адресам ходит каждая программа, и отправляет её целиком в нужный туннель одной кнопкой. Имя берётся с **запущенной** программы, а не набирается руками: движок сличает его точно, и `telegram` вместо `Telegram` молча не сработает. Для macOS-приложения правило ставится на все программы внутри бандла сразу — сеть открывает не оно само, а его помощник.
- **Раздел «Соединения»** — что идёт через туннель прямо сейчас: адрес, маршрут, программа, объём и скорость.

**Повседневное**

- **Проверка соединения** — один запрос напрямую и через каждый туннель; показывает IP выхода, страну и видит ли Cloudflare WARP. Про пропущенный туннель пишет, почему: не настроен, в подписке нет серверов, идёт через туннель, который не готов.
- **Добавить конфиг** — кнопкой, перетаскиванием `.conf` на окно или через **Ctrl+V** (файлом или текстом). Конфиг распознаётся по содержимому, расширение значения не имеет.
- **Раздел «Конфиги»** — текстовый редактор служебных файлов с профилями: несколько именованных вариантов туннеля и переключение в один клик.
- **Отчёт о проблеме** — одна кнопка в «Логах» собирает в файл версии, состояние туннелей, устройство конфига, состояние адаптера и лог. Ключи, адреса подписок и содержимое личных списков в отчёт не попадают, так что его можно пересылать не читая.
- **Сторож** — поднимает движок, если он упал, и не пытается перезапускать то, что перезапуском не чинится. Если поднимать не будет — пишет, почему.
- **Значок в трее** на всех трёх системах: состояние туннеля, запуск, остановка, перезапуск, окно и выход. Закрытие окна убирает Tunor с глаз, а не выключает — туннель живёт дальше.
- **Автозапуск** свёрнутым в трей (на Windows через планировщик, на macOS через LaunchAgent, на Linux через systemd-юнит `tunor.service`), **авто-перезапуск после сна**, **обновления по воздуху** с проверкой SHA256, тёмная тема, режим одного экземпляра.

## Установка

### Windows

1. Скачай **`Tunor-Setup.exe`** со страницы [Releases](../../releases/latest).
2. Запусти установщик — нужны права администратора.
3. При первом запуске прими условия и пройди короткий туториал; там же кнопка **«Скачать списки»**.
4. Сгенерируй конфиг WARP в [@warp_generator_bot](https://t.me/warp_generator_bot) и добавь его: кнопкой **«Добавить файл .conf»** на «Главной», перетаскиванием на окно или через **Ctrl+V**.
5. *(необязательно)* geo или свой VPN по ссылке — на вкладке «Туннели».
6. Нажми **«Запустить»**.

### macOS (Apple Silicon)

Проще всего одной командой — она скачает сборку, проверит контрольную сумму, положит рядом с собой и поставит движок:

```bash
curl -fsSL https://raw.githubusercontent.com/Vexorter42/Tunor/main/packaging/mac-install.sh | bash
```

Либо вручную: скачать **`Tunor-<версия>-arm64.dmg`** из релиза и перетащить Tunor в «Программы».

Сборка подписана **ad-hoc**, а не сертификатом разработчика Apple — аккаунта за проектом нет. Поэтому при первом запуске система скажет, что не смогла проверить приложение:

1. В первом окне нажми **«Готово»**.
2. **Системные настройки → Конфиденциальность и безопасность → «Все равно открыть»**.
3. Система спросит ещё раз — снова **«Все равно открыть»**. Подсвечена там кнопка «Переместить в Корзину», то есть не та.

Правый клик → «Открыть» на нынешних macOS уже не помогает, Apple этот путь убрала. Установка командой выше диалога не вызывает вовсе — она снимает метку «скачано из интернета» сама.

Дальше на «Главной» нажми **«Установить службу»**: пароль спросят один раз, и после этого «Запустить» и «Остановить» работают молча. Режим TUN требует прав root, и служба держит их за приложение — без неё пароль будут спрашивать при каждом запуске.

> Запускать программу **из самого образа** не надо: macOS в этом случае подменяет её временной копией в томе только для чтения, и обновиться оттуда нельзя. Приложение об этом предупредит.

Установщик и образ не содержат ничьих приватных ключей, адресов подписок и личных списков доменов — всё настраивается и скачивается на месте.

### Linux (x86-64)

Скачай **`Tunor-<версия>-x86_64.AppImage`** из релиза — это один файл, который работает
на любом дистрибутиве:

```bash
chmod +x Tunor-*.AppImage
./Tunor-*.AppImage
```

Рядом лежит `.tar.gz` для тех, кому привычнее распаковать папку.

Библиотеки рабочего стола внутрь не вкладываются — они принадлежат системе, и на любой
обычной графической установке уже стоят. Если запускаешь в голом окружении (контейнер,
WSL, сервер без десктопа), доставь их:

```bash
# Debian / Ubuntu
sudo apt install libx11-6 libxext6 libxrandr2 libxi6 libxcursor1 libxfixes3 libice6 libsm6 libfontconfig1 libgl1 libgtk-3-0

# Arch
sudo pacman -S --needed libx11 libxext libxrandr libxi libxcursor libxfixes libice libsm fontconfig libglvnd gtk3
```

**Режим TUN** требует права поднять сетевой интерфейс. Службы, как на macOS, здесь нет —
движок её на Linux не ставит. Вместо этого на «Главной» есть кнопка **«Выдать права
движку»**: она один раз вешает `cap_net_admin` на сам движок, и после этого пароль не
спрашивают **вовсе** — ни при запуске, ни потом. То же самое руками:

```bash
sudo setcap cap_net_admin,cap_net_raw+ep ~/.config/tunor/build/sing-box
```

Режим «только прокси» прав не требует совсем.

Скачанный AppImage — просто файл в папке загрузок, и десктоп о нём ничего не знает. На
вкладке **«Автозапуск»** есть кнопка **«Добавить в меню»**: она кладёт `.desktop` в твою
же папку `~/.local/share/applications`, без пароля, и так же убирается.

Файлы программа держит в `~/.config/tunor`, автозапуск — обычный user-юнит systemd
(`systemctl --user status tunor`).

## Какую версию AmneziaWG выбирать

Движок понимает все, так что выбирай любую:

| Версия | Параметры | Поддержка |
|---|---|---|
| AWG 1.0 | `S1–S4`, `Jc`, `Jmin`, `Jmax`, `H1–H4` | ✅ |
| AWG 2.0 | `I1–I5` | ✅ |
| AWG 3.0 | padding, rekey, reject, keepalive, handshake | ✅ |
| AWG 3.1 | `RandomTrailers`, `DisableCookies` | ✅ |

## Обновления по воздуху

Приложение читает `update.json` (репозиторий + зеркало), тянет `version.json` из последнего релиза и, если версия новее, скачивает сборку, сверяет `SHA256` и ставит её.

```json
{
  "repo": "Vexorter42/Tunor",
  "mirror": "https://ghproxy.net/"
}
```

Зеркало нужно там, где GitHub недоступен напрямую. Перестало работать — поменяй `mirror` (например на `https://ghfast.top/`), пересобирать ничего не нужно.

Один релиз несёт файлы для всех трёх систем, и приложение само берёт свой. Версия
общая — сборки делаются из одного дерева, — а файл и сумма у каждой свои:

```json
{
  "version": "1.11.5",
  "url":     ".../Tunor-Setup.exe",
  "sha256":  "…",
  "mac":   { "url": ".../Tunor-mac-arm64.tar.gz",     "sha256": "…" },
  "linux": { "url": ".../Tunor-1.11.6-x86_64.AppImage", "sha256": "…" }
}
```

На Windows обновление ставится установщиком в тихом режиме. На macOS и Linux приложение
не может заменить само себя на ходу — там скачанное кладётся рядом, а подмену делает
помощник: ждёт выхода приложения, отодвигает старое, ставит новое и запускает. Если
копирование не удалось, старое возвращается на место. На macOS подменяется бандл, на
Linux — файл AppImage; копия, запущенная из распакованной папки, говорит об этом прямо
и просит заменить её вручную.

## Сборка из исходников

Нужен [.NET SDK 8+](https://dotnet.microsoft.com/download).

```bash
# Windows
cd ui
dotnet publish -c Release -r win-x64 --self-contained true

# macOS (бандл собирается на любой системе)
cd desktop
dotnet publish -c Release -r osx-arm64 --self-contained true
python make-app.py            # -> build-mac/Tunor.app и Tunor-mac-arm64.tar.gz

# Linux (упаковка — на Linux, там appimagetool)
cd desktop
dotnet publish -c Release -r linux-x64 --self-contained true
bash make-appimage.sh         # -> build-linux/Tunor-<версия>-x86_64.AppImage и .tar.gz
```

Сборка установщика для Windows описана отдельно — см. [`packaging/README.md`](packaging/README.md).

**То, что раздаётся для macOS, собирается на маке**, и это не придирка: `codesign` есть только там, а .NET подписывает лишь исполняемый файл и не запечатывает бандл. Такой бандл запускается, пока ничто не пометило его как скачанный, и называется повреждённым, как только пометит:

```bash
bash make-dmg.sh [путь/к/Tunor.app] [куда/положить]
```

Скрипт подписывает бандл ad-hoc, пересобирает из подписанного `.tar.gz` для обновлений и делает `.dmg` с оформленным окном. Фон окна рисуется отдельно — `python make-dmg-background.py`.

### Проверка экранов без экрана

```bash
cd smoke
dotnet run
```

Открывает все страницы и окна приложения вхолостую и говорит, какие упали. Ловит то, что не ловит компилятор: ресурс, запрошенный до присоединения к дереву, обработчик, стреляющий внутри `InitializeComponent`, привязку к несуществующему свойству. Заодно печатает, что приложение видит о запущенном движке. Ничего не меняет; пересборку `config.json` включает только `TUNOR_SMOKE_WRITE=1`.

### Где что лежит

```
<корень>/
  settings.json            # режимы (tun / proxy / final / logging)
  update.json              # { "repo": "...", "mirror": "..." }
  THIRD-PARTY-NOTICES.md   # сведения о сторонних компонентах
  licenses/                # GPL-3.0.txt, sing-box-LICENSE.txt
  build/
    sing-box[.exe]         # движок (sing-box-lx, собран с тегом with_awg)
    sing-box.version       # какая это сборка движка и её sha256
    config.json            # генерируется приложением
  data/
    tunnels.json           # список туннелей и что через что идёт
    rules.json             # группы маршрутизации
    warp.conf              # AmneziaWG-конфиг WARP
    geo.conf               # WireGuard-конфиг geo
    cache.db               # кэш движка
    rulesets/*.srs         # локальные списки (скачиваются приложением)
  ui/Tunor.exe             # приложение (Windows)
```

На Windows корень — папка установки. На macOS и Linux программа живёт отдельно от своих
файлов: на macOS они в `~/Library/Application Support/Tunor`, на Linux — в
`~/.config/tunor` (или в `$XDG_CONFIG_HOME/tunor`, если он задан).

Исходники разложены так: `ui/` — приложение для Windows (WPF) и общий код служб, `core/` — тот же общий код как отдельная сборка без Windows-зависимостей (компилятор следит, чтобы в него не просочился Windows-API), `desktop/` — приложение для macOS на Avalonia, `smoke/` — проверка экранов, `packaging/` — сборка релиза.
