# Сборка релиза

Три файла: `stage.py` собирает дерево для установщика, `gen_config.py` делает стартовый
`config.json`, `tunor.iss` пакует всё в `Tunor-Setup.exe`.

## Что нужно

- [.NET SDK 8+](https://dotnet.microsoft.com/download)
- [Inno Setup 6](https://jrsoftware.org/isdl.php) — нужен `ISCC.exe`
- Python 3
- Рабочая копия установленного Tunor: из неё берутся движок, вспомогательные скрипты
  и шаблоны настроек. По умолчанию `C:/Program Files/ssnet`, меняется через `TUNOR_APP`.

## Порядок

```bash
# 1. версия
#    поднять <Version>, <FileVersion>, <AssemblyVersion> в ui/Tunor.csproj
#    и #define MyAppVersion в packaging/tunor.iss — они должны совпадать

# 2. сборка приложения
cd ui
dotnet publish -c Release -r win-x64 --self-contained true

# 3. дерево установщика (по умолчанию в build-out/dist)
cd ..
python packaging/stage.py

# 4. установщик (по умолчанию в build-out/out)
ISCC packaging/tunor.iss
```

Переменные окружения, если пути другие:

| Переменная | Что это | По умолчанию |
|---|---|---|
| `TUNOR_APP` | откуда брать движок и шаблоны | `C:/Program Files/ssnet` |
| `TUNOR_OUT` | куда складывать результат | `<репозиторий>/build-out` |
| `TUNOR_ENGINE` | конкретный `sing-box.exe` | `TUNOR_APP/build/sing-box.exe` |

## Что `stage.py` делает с личными данными

Результат публикуется, поэтому из него убирается всё, что относится к одной машине:

- **`settings.json`** берётся как образец, но из него удаляются `controllerSecret`,
  `controllerPort` и `listsUpdatedAt`; `accept` сбрасывается, чтобы мастер первого
  запуска показался заново.
- **`rules.json`** сохраняет структуру групп, но **все списки внутри заменяются** на
  `example.com` / `example.exe` — ни один личный домен или процесс наружу не уходит.
- **`warp.conf` и `geo.conf`** пишутся заново: случайные ключи, метка
  `TUNOR-PLACEHOLDER` и заведомо нерабочий эндпоинт. Приложение по этой метке понимает,
  что туннель ещё не настроен.
- **`.srs`-списки правил не вкладываются вообще** — приложение скачивает их из
  первоисточника при первом запуске, чтобы не распространять чужие файлы.

## Стартовый `config.json`

`gen_config.py` собирает конфиг из того, что лежит в дереве, а `stage.py` затем
**вычищает** из него то, чего на свежей машине быть не может: туннели, собранные из
файлов-заглушек, и наборы правил, чьи `.srs` не вложены. Иначе движок не запустился бы
с таким конфигом. Там же стоят проверки, что ни одно правило не ссылается на
исчезнувший тег.

Приложение всё равно пересобирает `config.json` при первом запуске новой версии —
вложенная копия нужна лишь до этого момента.

## Движок

Вкладывается неизменённый `sing-box.exe` сборки [sing-box-lx](https://github.com/Leadaxe/sing-box-lx).
Рядом пишется `sing-box.version` — версия, sha256 и ссылка на релиз; приложение
показывает это в отчёте о проблеме и сверяет хеш с файлом, который у него есть.

Как обновить движок:

1. скачать релиз, сверить архив с `SHA256SUMS`;
2. `ENGINE_VERSION` в `stage.py` — на новый тег, `TUNOR_ENGINE` — на распакованный файл;
3. в `tunor.iss` переключить `sing-box.exe` и `sing-box.version` с `onlyifdoesntexist`
   на `ignoreversion` и добавить `taskkill /f /im sing-box.exe` в секцию `[Code]`,
   иначе новый файл не запишется поверх работающего;
4. после релиза вернуть флаги обратно — иначе каждое следующее обновление будет
   ронять туннель без нужды.
