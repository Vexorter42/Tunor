# Tunor для Android

Ранняя версия: то же, что делает Tunor на компьютере, в объёме, который нужен телефону. Построена на движке
[sing-box-lx](https://github.com/Leadaxe/sing-box-lx), его библиотеке `libbox`, с AmneziaWG 1.0 / 2.0 / 3.x.

## Что есть

- **Туннели**, как на компьютере: **WARP** и **geo** (конфиги `.conf` WireGuard и AmneziaWG, файлом или текстом), и сколько угодно
  своих: ещё один `.conf`, ссылка `vless://` или подписка (адрес, который отдаёт список ссылок, обычным текстом или в
  base64) с выбором сервера. Все они работают одновременно, а правила решают, кому что. Любой можно пустить **внутри**
  другого: geo по умолчанию идёт внутри WARP, и его адрес виден только оттуда. Туннель, который не может работать, не
  роняет остальные: причина написана на его карточке.
- **Готовые списки** из того же каталога, что и на компьютере (`catalog/catalog.json`): отметил, список скачался, и эти
  сайты идут через WARP или geo (для каждого списка можно выбрать другой туннель). Каталог лежит внутри приложения, при
  открытии страницы приложение спрашивает у репозитория более новый; списки скачиваются с GitHub, а если он не отвечает,
  через зеркала, и обновляются сами раз в несколько дней. Изменения вступают в силу сразу, без перезапуска.
- **Свои сайты** (адрес покрывает и поддомены), каждый через выбранный туннель; они важнее готовых списков. **Всё остальное**
  идёт напрямую (скорость не страдает) или через выбранный туннель. И выбор приложений, которые вообще пользуются VPN.
- **Проверка соединения:** спрашивает у Cloudflare, откуда виден запрос, через каждый туннель и напрямую.
- **Журнал движка** на экране, условия использования при первом запуске.

## Чего пока нет

Обучения с вопросами (оно есть на компьютере), слежения за стабильностью туннеля, смены точки выхода WARP, ссылок
`vmess://`, `trojan://`, `ss://` (только `vless://`), правил для отдельных приложений (есть только выбор тех, кто
пользуется VPN), IPv6 (туннель и DNS работают по IPv4: телефонная сеть часто объявляет IPv6, которым нельзя
пользоваться), запуска при включении телефона и обновления по воздуху (новая версия ставится APK поверх старой).

## Как это проверено

На эмуляторе Android 16 против локальных серверов на том же движке, поднятых на компьютере:

- VLESS-сервер: VPN поднимается, сайт из списка приходит на сервер, сайт не из списка идёт напрямую;
- AmneziaWG-сервер с обфускацией (`Jc`, `S1`, `S2`, `H1`–`H4`): рукопожатие проходит, трафик выходит через сервер;
- подписка, поданная по адресу, с серверами, названными кириллицей и пробелами;
- WARP (AmneziaWG) и geo (WireGuard) вместе, причём адрес сервера geo доступен телефону только через WARP: сайты из
  правил идут каждый через свой туннель, а если выключить сервер WARP, geo тоже перестаёт отвечать;
- готовый список из каталога: отмеченный при включённом VPN, он скачивается и начинает работать без перезапуска;
- настройки, записанные прежней версией, подхватываются;
- несколько включений и выключений подряд, релизная сборка со сжатием кода.

На настоящем телефоне и с настоящим WARP это ещё не проверялось.

## Сборка

Нужны JDK 17 или новее и Android SDK с платформой 36 (`ANDROID_HOME` указывает на него).

```bash
cd android
python fetch-libbox.py            # движок, 120 МБ: в репозитории его нет. Где GitHub медленный: --mirror https://gh-proxy.com/
./gradlew :app:assembleDebug      # или :app:assembleRelease
```

APK по одному на архитектуру лежат в `app/build/outputs/apk/`: `arm64-v8a` для телефонов, `x86_64` для эмулятора.
Движок `fetch-libbox.py` сверяет с контрольной суммой, записанной в нём самом, поэтому зеркало может его
принести, но не подменить. Обновить движок — изменить `VERSION` и `SHA256` в этом файле.

Подпись выпуска берётся из `signing.properties` (его нет в репозитории): `storeFile`, `storePassword`, `keyAlias`,
`keyPassword`. Без него релиз подписывается отладочным ключом: ставится, но публиковать такой нельзя. Ключ
нужно беречь: приложение, подписанное другим, не обновляется поверх старого.

`python make-icons.py` рисует значок из логотипа приложения для компьютера.
