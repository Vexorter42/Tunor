# Tunor для Android

Ранняя версия: то же, что делает Tunor на компьютере, в объёме, который нужен телефону. Построена на движке
[sing-box-lx](https://github.com/Leadaxe/sing-box-lx), его библиотеке `libbox`, с AmneziaWG 1.0 / 2.0 / 3.x.

## Что есть

- **Туннели**, как на компьютере: **WARP** и **geo** (конфиги `.conf` WireGuard и AmneziaWG, файлом или текстом), и сколько угодно
  своих: ещё один `.conf`, ссылка `vless://` или подписка (адрес, который отдаёт список ссылок, обычным текстом или в
  base64) с выбором сервера. Все они работают одновременно, а правила решают, кому что. Любой можно пустить **внутри**
  другого: geo по умолчанию идёт внутри WARP, и его адрес виден только оттуда. Туннель, который не может работать, не
  роняет остальные: причина написана на его карточке.
- **Готовые списки** из того же каталога, что и на компьютере (`catalog/catalog.json`): отметил, список скачался, и эти
  сайты идут через WARP или geo (для каждого списка можно выбрать другой туннель). Каталог лежит внутри приложения, при
  открытии страницы приложение спрашивает у репозитория более новый; списки скачиваются с GitHub, а если он не отвечает,
  через зеркала, и обновляются сами раз в несколько дней. Изменения вступают в силу сразу, без перезапуска.
- **Свои сайты** (адрес покрывает и поддомены), каждый через выбранный туннель; они важнее готовых списков. **Всё остальное**
  идёт напрямую (скорость не страдает) или через выбранный туннель.
- **Приложения.** Для каждого можно выбрать, через что пойдёт его трафик: по правилам, как у всех; напрямую, мимо VPN
  совсем; или через один из туннелей, что бы оно ни открывало (это важнее и сайтов, и списков). Чьё соединение, спрашивается
  у системы, поэтому «через туннель» работает с Android 10; «напрямую» — на любом.
- **Плитка в шторке быстрых настроек:** туннель включается и выключается одним нажатием, не открывая приложение. В самом
  уведомлении, пока он работает, есть кнопка «Остановить». Плитку нужно добавить в шторку один раз, как любую другую.
- **Пинг серверов подписки** (время открытия TCP-соединения с портом сервера, три замера, берётся средний; пока туннель
  включён, измеряется путь мимо него), список по скорости и кнопка «Быстрейший».
- **Обход глушилок.** Если ни один обычный сервер подписки не отвечает, приложение само берёт из неё серверы со словами
  «обход», «глушилка» или «LTE» в названии, измеряет их и выбирает самый быстрый. Когда обычные серверы ответят снова (два
  раза подряд), возвращается на прежний. Смотрит на это, пока туннель работает: через несколько секунд после запуска, потом
  раз в пять минут и вскоре после смены сети. Не трогает телефон без сети и выбор, сделанный человеком. Выключается в «Ещё».
- **Обновление по воздуху.** «Ещё → Обновления» (и само, раз в полдня): приложение читает `version.json` последнего релиза,
  скачивает APK для своего процессора, сверяет SHA-256, пакет (то же имя, версия новее, **подписан тем же ключом**) и передаёт
  системе, которая спрашивает подтверждение. Система и сама откажется ставить то, что подписано другим ключом.
  Один раз нужно разрешить Tunor устанавливать приложения (приложение откроет нужный экран настроек).
- **Проверка соединения:** спрашивает у Cloudflare, откуда виден запрос, через каждый туннель и напрямую.
- **Журнал движка** на экране, условия использования при первом запуске.

## Чего пока нет

Обучения с вопросами (оно есть на компьютере), слежения за стабильностью туннеля, смены точки выхода WARP, ссылок
`vmess://`, `trojan://`, `ss://` (только `vless://`), IPv6 (туннель и DNS работают по IPv4: телефонная сеть часто
объявляет IPv6, которым нельзя пользоваться) и запуска при включении телефона.

## Как это проверено

На эмуляторе Android 16 против локальных серверов на том же движке, поднятых на компьютере:

- VLESS-сервер: VPN поднимается, сайт из списка приходит на сервер, сайт не из списка идёт напрямую;
- AmneziaWG-сервер с обфускацией (`Jc`, `S1`, `S2`, `H1`–`H4`): рукопожатие проходит, трафик выходит через сервер;
- подписка, поданная по адресу, с серверами, названными кириллицей и пробелами;
- WARP (AmneziaWG) и geo (WireGuard) вместе, причём адрес сервера geo доступен телефону только через WARP: сайты из
  правил идут каждый через свой туннель, а если выключить сервер WARP, geo тоже перестаёт отвечать;
- готовый список из каталога: отмеченный при включённом VPN, он скачивается и начинает работать без перезапуска;
- настройки, записанные прежней версией, подхватываются;
- приложение, отправленное через geo или напрямую: его запросы идут ровно туда, куда сказано, и выбор меняется без
  перезапуска;
- подписка, у которой все обычные серверы не отвечают: приложение само перешло на сервер «Обход LTE», а когда обычный
  сервер поднялся, вернулось на него; пинг и «Быстрейший»;
- плитка в шторке включает и выключает туннель;
- обновление по воздуху против локального манифеста: подпись другим ключом и подмена файла (SHA-256) отклоняются, настоящее
  обновление скачивается, проверяется и ставится, версия меняется;
- несколько включений и выключений подряд, релизная сборка со сжатием кода и с настоящим ключом подписи.

На настоящем телефоне и с настоящим WARP это ещё не проверялось.

## Сборка

Нужны JDK 17 или новее и Android SDK с платформой 36 (`ANDROID_HOME` указывает на него).

```bash
cd android
python fetch-libbox.py            # движок, 120 МБ: в репозитории его нет. Где GitHub медленный: --mirror https://gh-proxy.com/
./gradlew :app:assembleDebug      # или :app:assembleRelease
```

APK по одному на архитектуру лежат в `app/build/outputs/apk/`: `arm64-v8a` для телефонов, `x86_64` для эмулятора.
Движок `fetch-libbox.py` сверяет с контрольной суммой, записанной в нём самом, поэтому зеркало может его
принести, но не подменить. Обновить движок — изменить `VERSION` и `SHA256` в этом файле.

Подпись выпуска берётся из `signing.properties` (его нет в репозитории): `storeFile`, `storePassword`, `keyAlias`,
`keyPassword`. Без него релиз подписывается отладочным ключом: ставится, но публиковать такой нельзя. Ключ
нужно беречь и хранить копию: приложение, подписанное другим, не обновляется поверх старого, ни вручную, ни по воздуху.

## Выпуск

1. Поднять `versionCode` (число, по которому приложения решают, что есть новее) и `versionName` в `app/build.gradle.kts`.
2. `./gradlew :app:assembleRelease`, файлы из `app/build/outputs/apk/` переименовать в
   `Tunor-android-<версия>-arm64-v8a.apk` и `Tunor-android-<версия>-x86_64.apk`.
3. `python release-manifest.py <version.json релиза> <папка с APK> <тег релиза> <версия> <versionCode> "что нового"` дописывает
   в манифест секцию `android` с адресами и контрольными суммами. Остальное в манифесте (части для Windows, macOS и Linux) не
   меняется.
4. Загрузить APK и `version.json` в релиз. Приложения читают `version.json` именно последнего релиза, поэтому в каждом
   следующем релизе секция `android` должна быть, иначе у них не будет обновления.

В сборке для отладки (`BuildConfig.DEBUG`) можно, чтобы не ждать релиза, положить в папку приложения `ota-url.txt` с адресом
своего манифеста и `health-seconds.txt` с числом секунд между проверками серверов подписки.

`python make-icons.py` рисует значок из логотипа приложения для компьютера.
