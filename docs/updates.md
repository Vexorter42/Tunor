# Обновления по воздуху

Приложение читает `update.json` (репозиторий + зеркало), тянет `version.json` из последнего релиза и, если версия новее, скачивает сборку, сверяет `SHA256` и ставит её.

```json
{
  "repo": "Vexorter42/Tunor",
  "mirror": "https://gh-proxy.com/"
}
```

Приложение идёт за файлами на GitHub напрямую, а через `mirror` — только если GitHub не ответил за 12 секунд; запасные зеркала (`gh-proxy.com`, `ghfast.top`) встроены, так что одно умершее зеркало больше ничего не ломает. Пустой `mirror` — только GitHub и никаких посредников. До 2.0.7 был только зеркальный путь: когда `ghproxy.net` перестал отвечать, обновиться из приложения было нельзя — такие версии обновляются вручную, скачав установщик со страницы релиза.

## Какие файлы где лежат

Релиз программы для компьютера (`vX.Y.Z`) несёт файлы Windows, macOS и Linux и `version.json`, и приложение само берёт свой. Версия общая у компьютерных сборок — они делаются из одного дерева, — а файл и сумма у каждой свои. У Android версия своя (`0.4.x`), и он выходит отдельным релизом `android-vX.Y.Z`, не помеченным «последним»: в `version.json` последнего релиза его файлы описывает отдельный раздел.

```json
{
  "version": "2.3.0",
  "url":     ".../Tunor-Setup.exe",
  "sha256":  "…",
  "mac":     { "url": ".../Tunor-mac-arm64.tar.gz",       "sha256": "…" },
  "mac-x64": { "url": ".../Tunor-mac-x64.tar.gz",         "sha256": "…" },
  "linux":   { "url": ".../Tunor-2.3.0-x86_64.AppImage", "sha256": "…" },
  "android": {
    "version": "0.4.0",
    "code": 5,
    "arm64-v8a": { "url": ".../android-v0.4.0/Tunor-android-0.4.0-arm64-v8a.apk", "sha256": "…", "size": 29505403 },
    "x86_64":    { "url": ".../android-v0.4.0/Tunor-android-0.4.0-x86_64.apk",    "sha256": "…", "size": 31441561 }
  }
}
```

`version.json` читается по адресу `releases/latest/download/version.json`, то есть из **последнего** релиза репозитория. Поэтому последним всегда остаётся релиз программы для компьютера: на его файлы ссылаются `releases/latest/download/...` в README и установочный скрипт для macOS, а релиз только с APK их сломал бы. Android выходит отдельным релизом, и после загрузки APK в манифест последнего релиза дописывается раздел `android` (порядок — в [`android/README.md`](../android/README.md#выпуск)). Манифест следующей компьютерной версии должен нести этот раздел, иначе у телефонов пропадёт обновление.

## Как ставится

- **Windows** — установщик запускается в тихом режиме.
- **macOS и Linux** — приложение не может заменить само себя на ходу: скачанное кладётся рядом, а подмену делает помощник. Он ждёт выхода приложения, отодвигает старое, ставит новое и запускает. Если копирование не удалось, старое возвращается на место. На macOS подменяется бандл, на Linux — файл AppImage; копия, запущенная из распакованной папки, говорит об этом прямо и просит заменить её вручную.
- **Android** — приложение скачивает APK для своего процессора, сверяет `SHA256`, проверяет имя пакета, версию и **подпись тем же ключом**, и передаёт пакет системе, которая спрашивает подтверждение. Принимаются только адреса вида `https://github.com/Vexorter42/Tunor/releases/download/…`, из любого релиза этого репозитория. Подробнее — в [`android/README.md`](../android/README.md).

Автоматический поиск выключается в настройках (на Android — «Ещё → Обновления»).
